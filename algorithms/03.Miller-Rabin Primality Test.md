## 1. What Does It Mean for a Number to Be Prime?

A number `n > 1` is **prime** if it has exactly two divisors:

```
1 and n
```

Everything else is **composite**.

---

## 2. Fermat’s Little Theorem — The True Foundation

### 2.1 Why Primes Are Special Modulo n

When `n` is **prime**, the numbers:

```
1, 2, 3, ..., n−1
```

form a **multiplicative group modulo n**:

* Every number has an inverse
* No multiplication causes collisions
* Arithmetic is perfectly reversible

This property is **unique to primes**.

---

### 2.2 Intuition Behind Fermat’s Little Theorem

Pick any number `a` such that:

```
1 ≤ a < n,  gcd(a, n) = 1
```

Multiply all numbers `1..n−1` by `a` modulo `n`:

```
1·a, 2·a, 3·a, ..., (n−1)·a   (mod n)
```

Because `n` is prime:

* This is just a **reordering** of `1..n−1`
* No value disappears or duplicates

So:

```
1·2·3·...·(n−1)
≡ (1·a)(2·a)(3·a)...((n−1)·a)  (mod n)
```

Simplify:

```
(n−1)! ≡ a^(n−1) · (n−1)!   (mod n)
```

Cancel `(n−1)!` (allowed only because n is prime):

```
a^(n−1) ≡ 1 (mod n)
```

👉 This is **why the equation signals primality**.

---

### 2.3 Concrete Example (Prime)

```
n = 7, a = 3
Numbers: 1 2 3 4 5 6
Multiply by 3 mod 7:
3 6 2 5 1 4   (same set reordered)
```

Product unchanged ⇒

```
3^6 ≡ 1 (mod 7)
```

---

### 2.4 Why Fermat Fails for Composites

If `n` is composite:

* Some numbers **do not have inverses**
* Multiplication causes **collisions**
* Cancellation becomes invalid

Yet some composites *accidentally* satisfy:

```
a^(n−1) ≡ 1 (mod n)
```

These are **Fermat liars**.

---

### 2.5 Why Squaring Matters (The Missing Structure)

Exponentiation is built from **repeated squaring**.

Rewrite:

```
n−1 = d × 2^s   (d odd)
```

This produces a squaring chain:

```
a^d → a^(2d) → a^(4d) → ... → a^(n−1)
```

Fermat checks **only the last value**.

Miller–Rabin checks the **entire chain**.

---

### 2.6 Why −1 Is the Only Gateway to 1 (For Primes)

For a prime `p`, the equation:

```
x^2 ≡ 1 (mod p)
```

has **only two solutions**:

```
x ≡ 1 or x ≡ −1
```

This means:

* The only way to reach `1` by squaring
* Is to square `−1`

---

### 2.7 Why This Is the Core of Miller–Rabin

If during squaring you see:

```
1 (without seeing −1 first)
```

Then:

* A non‑trivial square root of 1 exists
* This is **impossible for primes**

👉 **Composite detected**.

## 3. Fermat Primality Test (Naive)

Algorithm:

1. Pick a base `a`
2. Compute `a^(n−1) % n`
3. If result ≠ 1 → composite
4. Else → probably prime

### Problem

Some composite numbers **pass this test**.

---

## 4. Fermat Fails: Carmichael Numbers

### Example

```
561 = 3 × 11 × 17
2^560 ≡ 1 (mod 561)
```

561 is composite, yet Fermat says “prime”.

❌ Fermat checks **only the final result**, not the path.

---

## 5. Key Insight: Look Inside the Exponentiation

Rewrite:

```
n − 1 = d × 2^s   (d is odd)
```

This exposes a **chain of squarings**:

```
a^d → a^(2d) → a^(4d) → ... → a^(n−1)
```

Miller–Rabin examines this chain.

---

## 6. Crucial Number Theory Fact (Why This Works)

For a **prime** number `p`:

```
x^2 ≡ 1 (mod p)
```

has **only two solutions**:

```
x ≡ 1 or x ≡ −1 (mod p)
```

### Example (p = 7)

```
1^2 ≡ 1
6^2 ≡ 36 ≡ 1 (mod 7)
```

No other number works.

---

## 7. What Goes Wrong for Composite Numbers

Composite numbers may have **extra square roots of 1**.

### Example (561)

```
67^2 ≡ 1 (mod 561)
67 ≠ ±1
```

🚨 This is impossible for primes.

---

## 8. Miller–Rabin Core Idea

Instead of only checking:

```
a^(n−1) ≡ 1
```

We check **how we reach 1**.

If `n` is prime:

* The only way to reach `1` is:

```
−1 → square → 1
```

Any deviation ⇒ composite.

---

## 9. Miller–Rabin Test Rules

Let:

```
x0 = a^d % n
x1 = x0^2 % n
x2 = x1^2 % n
...
xs = a^(n−1) % n
```

### Accept (probably prime) if:

* `x0 == 1`, OR
* Some `xr == n−1`

### Reject (composite) if:

* You reach `1` **without seeing `n−1` first**

---

## 10. Worked Example — Prime (n = 23)

```
22 = 11 × 2^1
```

Base `a = 2`

```
x0 = 2^11 % 23 = 1
```

✔ Prime-like behavior

## 11. Worked Example — Composite (n = 21)

```
20 = 5 × 2^2
```

Base `a = 2`

```
x0 = 2^5 % 21 = 11
x1 = 11^2 % 21 = 16
```

No `−1` → ❌ composite

## 12. Carmichael Number Example — 561

```
560 = 35 × 2^4
```

Base `a = 2`

```
x0 = 2^35 % 561 = 263
x1 = 263^2 % 561 = 166
x2 = 166^2 % 561 = 67
x3 = 67^2 % 561 = 1  ❌
```

Reached `1` without seeing `−1` → composite detected

This guarantees correctness for `n < 2^64`.

## 19. Why −1 ≡ n−1 (mod n)

### Formal Proof

Two numbers `a` and `b` are congruent modulo `n` if:

```
a ≡ b (mod n)  ⇔  n | (a − b)
```

Apply to `−1` and `n−1`:

```
(n − 1) − (−1) = n
```

Since `n` divides `n`:

```
−1 ≡ n − 1 (mod n)
```

So in modular arithmetic, `−1` and `n−1` represent the **same value**.

---

### Intuition (Circular Number Line)

Modulo `n` behaves like a circle:

```
0 → 1 → 2 → ... → n−2 → n−1 → 0 → ...
```

* `−1` means “one step backward from 0”
* That lands at `n−1`

Hence:

```
−1 mod n = n−1
```

---

### Why This Matters in Miller–Rabin

For a **prime** `p`:

```
x² ≡ 1 (mod p)
```

has only two solutions:

```
x ≡ 1 or x ≡ −1 (≡ p−1)
```

During the squaring chain:

* Seeing `p−1` means we found the **only legal gateway** to `1`
* Reaching `1` without seeing `p−1` proves compositeness

## 20. Miller–Rabin Algorithm — Pseudocode

### High-Level Pseudocode

```
function isPrime(n):
    if n < 2: return false
    if n == 2 or n == 3: return true
    if n is even: return false

    write n−1 = d × 2^s   (d odd)

    for each base a in testBases:
        if a >= n: continue
        if not millerTest(a, d, s, n):
            return false

    return true
```

---

### Miller Test (Single Base)

```
function millerTest(a, d, s, n):
    x = powmod(a, d, n)

    if x == 1 or x == n−1:
        return true

    repeat s−1 times:
        x = (x × x) mod n
        if x == n−1:
            return true

    return false
```
