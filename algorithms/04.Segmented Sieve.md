# Segmented Sieve of Eratosthenes

## 1. Problem Statement

Find all **prime numbers in a range**:

```
[L, R]
```

where:

* `R` can be very large
* `R - L` can also be large
* Available memory is limited

---

## 2. Why the Classic Sieve Fails

### Classic Sieve of Eratosthenes

* Builds an array of size `N + 1`
* Marks multiples of each prime

### Complexity

* Time: `O(N log log N)`
* Space: `O(N)`

### Problem

* `N = 10^9` → too much memory
* `N = 10^12` → impossible

We need a **memory-efficient approach**.

---

## 3. Key Mathematical Insight

Any composite number `x` has **at least one prime factor ≤ √x**.

Therefore:

> To mark all composite numbers in `[L, R]`, we only need **all primes ≤ √R**.

This observation is the **foundation of the segmented sieve**.

---

## 4. Core Idea of Segmented Sieve

Instead of sieving `[2 … R]`:

1. Precompute primes up to `√R`
2. Divide `[L, R]` into smaller segments
3. Sieve each segment using the small primes
4. Collect unmarked numbers as primes

---

## 5. Algorithm Overview

### Step 1: Precompute Small Primes

Use the classic sieve to compute all primes up to:

```
limit = floor(√R)
```

Store them in a list `smallPrimes`.

---

### Step 2: Segment the Range

Choose a segment size `S` (e.g., `100,000` or `1,000,000`).

Process ranges:

```
[L … L+S−1]
[L+S … L+2S−1]
...
```

Only one segment is kept in memory at a time.

---

### Step 3: Sieve a Segment

For a segment `[segmentL, segmentR]`:

Create a boolean array:

```
isComposite[0 … segmentR − segmentL]
```

Index mapping:

```
index i → number (segmentL + i)
```

---

### Step 4: Mark Composites

For each prime `p` in `smallPrimes`:

Find the first multiple of `p` in the segment:

```
start = max(p*p, ceil(segmentL / p) * p)
```

Implementation logic:

* `p*p` avoids re-marking smaller multiples
* `ceil` ensures the start lies inside the segment

Mark multiples:

```
for x = start to segmentR step p:
    isComposite[x − segmentL] = true
```

---

### Step 5: Collect Primes

For each index `i`:

```
number = segmentL + i
```

If:

* `isComposite[i] == false`
* `number > 1`

Then `number` is prime.

---

## 6. Correctness Argument

* Every composite number has a prime factor ≤ `√R`
* All multiples of those primes are marked
* Remaining numbers cannot be composite
* Therefore, remaining numbers are prime

---

## 7. Time and Space Complexity

### Time Complexity

| Phase              | Complexity                 |
|--------------------|----------------------------|
| Sieve up to √R     | `O(√R log log √R)`         |
| Segment processing | `O((R − L + 1) log log R)` |

### Space Complexity

| Component    | Space              |
|--------------|--------------------|
| Small primes | `O(√R)`            |
| One segment  | `O(segment size)`  |
| Total        | Independent of `R` |

---

## 8. Segment Size Selection

Segment size affects **performance**, not correctness.

Typical values:

```
100,000 – 1,000,000
```

* Too small → excessive loop overhead
* Too large → cache misses, higher memory pressure

---

## 9. Multi-Segment Processing

If `R − L` is very large:

* Process segments sequentially
* Reuse the same `smallPrimes`
* Keep only one segment array in memory

This avoids memory explosion.

---

## 10. Common Pitfalls

### Incorrect start calculation

```
(L + p − 1) / p   // WRONG (missing * p)
```

Correct:

```
((L + p − 1) / p) * p
```

### Incorrect indexing

```
isComposite[x]   // WRONG
```

Correct:

```
isComposite[x − segmentL]
```

### Forgetting edge cases

* `0` and `1` are **not prime**

---

## 11. Fundamental Limitation of Segmented Sieve

Segmented sieve **requires all primes ≤ √R**.

If:

```
√R > Integer.MAX_VALUE ≈ 2.147 × 10^9
```

Then:

* Classic sieve cannot generate required primes
* Memory and time become infeasible

This occurs when:

```
R > (Integer.MAX_VALUE)^2
R > 4.611686014132420609 × 10^18
```

This is a **mathematical limit**, not an implementation issue.

---

## 12. What Segmented Sieve Cannot Do

| Claim                                  | Reality      |
|----------------------------------------|--------------|
| Sieve up to `Long.MAX_VALUE`           | ❌ Impossible |
| Work when √R exceeds `int` range       | ❌            |
| Be fixed by more segmentation          | ❌            |
| Be solved by switching `int` to `long` | ❌            |

---

## 13. Alternatives Beyond the Limit

When `√R` is too large:

### 1. Trial Division

* Precompute primes up to a smaller bound (e.g., `10^6`)
* Test each number individually

### 2. Probabilistic Primality Tests

* Miller–Rabin
* Baillie–PSW

Used in cryptography and large-number primality testing.

---

## 14. Decision Guide

| Scenario              | Best Approach   |
|-----------------------|-----------------|
| `N ≤ 10^7`            | Classic sieve   |
| Range up to `10^12`   | Segmented sieve |
| Huge `R`, small range | Trial division  |
| 64-bit numbers        | Miller–Rabin    |

---

## 15. Key Takeaways

* Segmented sieve is a **memory optimization**
* Its strength comes from the `√R` observation
* Its limitation is **`√R` itself**
* Beyond that limit, the algorithm **must change**
